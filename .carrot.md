## Decisions

- **`save` writes to the current directory when there is no repository**, rather
  than refusing. `Repo.root` falls back to `Dir.pwd`; `Repo.in_repo?` reports
  which case applies. The CLI's `ensure_repo!` became `prepare!` and no longer
  raises — it only clears memoized git state.
- The CLI warns when there is no repository, because an uncommitted note does not
  survive a machine swap. Silent success would misrepresent how durable it is.
- A misplaced note is recoverable by moving it. No note is not, and the whole
  point of the tool is that there is one. Offered as "just do it" versus "make
  me pass a flag first"; the first won.
- The use is not limited to switching between *different* agents. A session that
  dies from a power cut or a dropped connection is the identical problem to the
  next session, and that is the case that actually prompted the change.

### 2026-10-08, extra sections

- **Extra sections are rendered, not parsed-and-forgotten.** `save` rewrites the
  whole file, so "never rendered" means "deleted" rather than "hidden". That
  makes writing them back out a correctness requirement, not a nicety: the tool's
  entire reason for existing is that hand-written content survives, and a note
  carrying a heading the tool does not recognize is precisely the case where it
  has no other copy.
- **`Record` keeps the heading as written rather than reconstructing it.** The
  slug is lossy — `normalize` collapses every run of non-alphanumerics to `_` —
  so `Decisions (2026-10-07)` and `Decisions 2026 10 07` are the same key and a
  reconstructed heading would mangle the author's on every save. Storing the
  original costs one hash; the alternative is unrecoverable.
- **Extras render after the canonical sections.** `SECTIONS` order is the
  documented display order (AGENTS.md section 7), so appending preserves it.
  Interleaving would have meant teaching the renderer about position, for no
  reader benefit.
- **The smoke test was corrected, not reverted around.** The obvious move when a
  long-red test blocks a branch is to skip it. That would have hidden the real
  reason `main` was red — a deliberate behaviour change whose test was never
  updated — and left the next agent to rediscover it. Asserting the warning text
  documents the intended contract instead.
- **Dated context goes under `###`, not as its own `##`.** Learned the hard way
  while writing this section: `## State` is regenerated from git on every save, so
  a `###` block that accidentally lands *above* the next `##` heading is treated
  as part of `State` and silently deleted on the next save. Sibling headings
  cannot be used as edit anchors for content that belongs to the previous
  section.

**Do not use a sibling `##` heading as an edit anchor.** A `###` block inserted
directly *above* `## Tried and failed` becomes part of `## State`, and `State` is
regenerated from git on every save — so the block is deleted on the very next
`save`. This is not a bug and not a regression; it is `State` doing the one job
the tool documents for it. It cost a rewrite here, and the same mistake is easy
to repeat on any note that keeps dated context. Anchor edits to unique prose
inside the target section instead.
